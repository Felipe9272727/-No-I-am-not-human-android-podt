# Room scene manifest

`room_manifest.json` is the reconstructed machine-readable setup for the seven room views in Unity `level1`. It records the serialized room-provider PPtrs, room view component IDs, local GameObject and Transform/RectTransform hierarchy, active flags, ordered character/object/narrative/button references, sprite-bearing Images, and each room view's linked Camera and serialized camera settings. Every Unity reference retains its file ID and file-local path ID.

The manifest is generated by `tools/reverse-rooms/export_room_manifest.py` and checked by `tools/reverse-rooms/validate_room_manifest.py`. The exporter loads only `level1`, `sharedassets0.assets`, `sharedassets1.assets`, and `globalgamemanagers.assets`. It uses static UnityPy parsing and the `MonoScript` table to map custom MonoBehaviours to retained `Assembly-CSharp` type declarations. The custom room/provider, narrative, and button field layouts are decoded from their retained serialized field declarations and checked against the source object's byte size. The exact Image/Sprite assignment is retained with the PPtr's byte offset (Unity UI Image m_Sprite slot, raw offset 88).

Observed source counts are seven room views, 104 descendant GameObjects, 79 button references in room arrays, 80 `UIButton` components in the scene, and nine `NarrativeRoomObject` components. One additional `UIButton` on `BreakdancingCockroach (1)` is not referenced by any room view's `_uiButtons` array. The nine serialized narrative enum, node, and position records match the nine native `narrative_objects()` records; the manifest keeps the source scene component IDs and GameObject names as well.

Each room root is serialized inactive at scene load. Six room views reference Camera component 2060 (`Main Camera`); `EntranceRoomView` references Camera component 2059 (`PeepholeCam`). The actual source geometry is supplied through local RectTransforms. These values are not treated as screen-space hit boxes: `UIButton.IsMousePosInSpriteArea` performs camera-aware RectTransform conversion and samples sprite alpha. The precise runtime hit region depends on the sprite alpha and camera; no rectangular hit areas are fabricated.

The earlier lost-manifest note cited 83 interactables. This extraction resolves 80 scene `UIButton` components, 79 assigned through room arrays, and nine narrative components (which point to buttons). It preserves that source evidence and does not add synthetic entries to force the historical total. Components without an unambiguous Sprite PPtr remain represented as unresolved/null rather than guessed.

Source evidence includes Unity `level1` path IDs, `globalgamemanagers.assets` MonoScript IDs, shared asset file/path IDs for sprites, the checked-in enum and narrative records in `reconstruction/native-game/src/rooms.cpp`, and retained C# declarations under `reconstruction/logic/cpp2il_cs/DiffableCs/Assembly-CSharp`.
