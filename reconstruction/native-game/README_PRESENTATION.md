# Presentation state and render data

`presentation.hpp` and `presentation.cpp` provide renderer-facing state for room poses, dialog emotion, examination signs, gun visibility, and character pose-change commands. The API is independent of Android drawing: callers can consume `RoomRenderPacket`, `DialogRenderPacket`, `SignRenderPacket`, and pending pose-change events.

Run `python3 tools/reverse-scenes/generate_presentation_provider.py` to rebuild `generated/presentation_provider.hpp` from the retained scene render manifest, `reverse-characters/emotion_registry.json`, and the recovered literal `EDialogEmotionState` C# enum. It preserves Unity file IDs and path IDs for each room pose, emotion sprite and animation frame, and human/imposter sign asset. The generated catalog includes all 61 scene characters, room component and GameObject identities, authored visibility and starting pose, and animation cycling/FPS values.

`room_packet(name)` starts from the authored pose and resolves the live pose to its exact sprite, local position, local scale, and `CannotInteract` value. `change_pose` updates the live pose immediately; `change_pose_tomorrow` schedules a pose, and `apply_tomorrow_poses` applies that schedule only when the caller signals the day transition. Each packet carries scene component, GameObject, character type, room, and source asset identities. `set_dialog_companion` selects the source character and `set_emotion` accepts enum names or integer values. `current_dialog_packet` resolves that character's first matching animation record, literal emotion value, frame data, and optional transform override; it returns no packet when the character or emotion is not selected or the source has no matching emotion. The dialog transform helpers use position `(DialogPosition.x + override.x, DialogPosition.y + override.y, 0)` and scale `(DialogScale, DialogScale, DialogScale) + override.Scale`. `setup_gun` records either bool value emitted by `GunSetUp`. `SceneCommandRouter` separately requires and invokes the character-manager adapter for `SetupGun(true)` and `DontSetupGun`; the latter does not change visibility. The presentation-only `dont_setup_gun()` reports Unsupported rather than queuing an action that a caller might accidentally execute twice. The downstream gameplay effect belongs to the character manager. `show_sign` selects the character's human or imposter evidence and `stop_showing_sign` clears the active packet.

`show_player_sign` returns `Unsupported` after validating its sign argument. The retained `CharacterCatalog` has no Sanya0/player `CharacterSOData` record, and the scene manifest contains no evidence that identifies another record as the player sign source. This avoids silently rendering an unrelated NPC. Sign records with absent source assets also return `Unsupported`; invalid names and missing characters have distinct results.

The provider preserves authored source data but does not render pixels. Screen dimensions, safe area, animation elapsed time, and random eye-motion targets remain runtime inputs. Game/session integration should treat `Applied` as a state/event update and handle `Unsupported`, `NotFound`, and `InvalidValue` explicitly.
