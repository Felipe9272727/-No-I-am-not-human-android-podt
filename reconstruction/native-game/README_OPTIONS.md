# Yarn option metadata behavior

`options.cpp` maps the exact original `LineMetadata` tags to the tag-specific behavior observed in `FakeOptionView.set_Option`. The production metadata lookup is generated by `python tools/reverse-localization/generate_line_metadata_provider.py` from the verified `reconstruction/reverse-localization/line_metadata.json`; `build_host.py` runs this generator before compiling. The policy layer does not render controls, localize text, simulate availability, decrement energy, alter inventory, or emulate the full Unity UI.

The native setter first selects `EDialogButtonStyle.Default` (0). It then checks tags in source order. `energy` selects style 2 and registers the `ConsumeEnergy` callback; `get_item` selects style 3; `give_item` selects style 4; `gun` selects style 5; `day_dialog` resets the option text to the line's text and registers `OnDayDialogSelected`; `skip` selects style 7; and `rude` registers `WereBadBoy`. `get_item`, `give_item`, `gun`, and `skip` only select styles in this setter. If multiple style tags are present, each later `SelectStyle` overwrites the earlier one, with `skip` last. The callback registration order is `energy`, `day_dialog`, then `rude`; current graph tags do not combine those callback tags on one choice. `lastline` is preserved in the metadata provider but has no branch in this setter.

The three `FakeOptionView` wrapper callbacks forward their runner events: `ConsumeEnergy` raises `FakeDialogRunner.EnergyConsumed`, `OnDayDialogSelected` raises `DayDialogSelected`, and `WereBadBoy` raises `WereBadBoy`. The `FakeDialogRunner` wrapper methods invoke their event delegates when present. These are event signals only; in particular, the `energy` tag does not establish an amount or prove a numeric cost.

Native body evidence is in `reconstruction/logic/recovered_isil/Assembly-CSharp/_Code/DialogSystem/FakeOptionView.txt` and `FakeDialogRunner.txt` (same bytes as the Cpp2IL `IsilDump` copies). The source is the original `GameAssembly.dll`, SHA-256 `1b27addf3cfddfaa2cb9e592170fd427e29dca58a58736a7468041af9e22f7bb`; it was only parsed/disassembled, never executed. Entry points below were checked against the original DLL bytes and PE exception-function ranges; addresses are image-base virtual addresses. The short runner event-forwarders are leaf functions without PE unwind entries, so their entry VAs were identified by decoding the byte sequences leading to the recorded conditional-return target and checking their complete disassembly against the ISIL body.

`options_tests.cpp` checks exact recovered IDs for `energy`, `day_dialog`, `get_item`, `give_item`, `gun`, `skip`, and `rude`, plus a known untagged ID and an unknown ID. The source callback methods carry no cost argument and tests assert only event signals. Unknown metadata remains explicitly distinguishable (`line_id_known == false`); this host adaptation throws before callback dispatch so a missing tag record cannot silently trigger a choice callback. That exception behavior is a safety guard in this port, not a claim about the original UI.
